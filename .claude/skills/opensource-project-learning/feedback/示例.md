# 自迭代机制使用示例

## 📖 完整流程示例

假设用户在学习 claude-hud 项目时遇到了问题。

### 步骤 1: 记录坑点

编辑 `feedback/坑点记录.md`，添加：

```markdown
### TypeScript 类型解释不够详细

**发现时间**: 2026-05-03
**严重程度**: 🟡 中
**项目类型**: 插件系统
**技术栈**: TypeScript

**问题描述**:
用户表示不熟悉 TypeScript，但 skill 提供的类型解释过于技术化，不理解 interface 和 type 的区别。

**影响范围**:
- 影响用户数量: 1人（首次发现）
- 影响学习阶段: 第2阶段（架构理解）
- 阻碍程度: 部分阻碍

**复现步骤**:
1. 用户说："我不熟悉 TypeScript"
2. Skill 提供了类型相关解释
3. 用户表示不理解

**期望行为**:
Skill 应该提供 TypeScript 的背景、与 JavaScript 的对比、基础概念详细解释。

**实际行为**:
Skill 只是简单提到了类型，没有深入解释。

**状态**: 🔄 待处理
```

### 步骤 2: 运行评估脚本

```bash
cd D:\vscode_proj\claude-hud-demo\.claude\skills\opensource-project-learning
bash scripts/evaluate-iteration.sh
```

**预期输出**：

```
🔍 评估是否需要迭代 skill...

📊 当前待处理坑点数: 1
📋 待处理的坑点:
  ### TypeScript 类型解释不够详细

📊 优先级分布:
  🔴 高优先级: 0
  🟡 中优先级: 1
  🟢 低优先级: 0

⏸️ 暂不触发迭代: 坑点数量未达到阈值
```

因为只有1个中优先级坑点，未达到阈值（需要3个），所以暂不触发。

### 步骤 3: 继续积累坑点

假设我们又记录了2个类似的中优先级坑点，再次运行评估：

```bash
bash scripts/evaluate-iteration.sh
```

**输出**：

```
✋ 触发迭代: 检测到3个或以上中优先级坑点

📁 创建迭代工作区: round-1
✓ 工作区创建完成: iteration/round-1

🚀 下一步操作:
  1. 查看问题: cat iteration/round-1/problems.md
  2. 生成技术方案: 调用 solution-generator agent
  3. 评估方案: 调用 solution-evaluator agent
```

### 步骤 4: 生成技术方案

在 Claude Code 中执行：

```javascript
// 使用 solution-generator agent
const generator = await Agent({
  subagent_type: "general-purpose",
  prompt: `
读取 agents/solution-generator.md 的指令，
然后为 iteration/round-1 生成技术改进方案。

输入：
- 问题列表: iteration/round-1/problems.md
- 当前 skill: .claude/skills/opensource-project-learning/
- 迭代历史: feedback/迭代历史.md

请生成详细的技术方案。
  `
});
```

或者简单地说：

```
"使用 solution-generator agent 为 iteration/round-1 生成技术方案"
```

### 步骤 5: 评估方案

方案生成后，评估方案质量：

```
"使用 solution-evaluator agent 评估 iteration/round-1/solution.md"
```

**预期结果**：

```
📊 评估结果

总分: 7.5/10
判定: ⚠️ 需完善

各维度评分:
| 维度       | 得分 | 权重 | 加权得分 |
|------------|------|------|----------|
| 问题覆盖度 | 8/10 | 20%  | 1.6     |
| 方案具体性 | 6/10 | 25%  | 1.5     |
| 可行性     | 9/10 | 20%  | 1.8     |
| 预期效果   | 7/10 | 20%  | 1.4     |
| 风险评估   | 8/10 | 15%  | 1.2     |

⚠️ 不足之处:
1. 方案具体性不足 (6/10)
   - 影响: 难以直接实施
   - 建议: 需要提供具体的代码示例和修改内容

💡 改进建议:
1. 增加具体的 TypeScript 教程内容
   - 当前问题: 只有"提供更多解释"的模糊建议
   - 如何改进: 在 references/ 中新增 typescript-basics.md
   - 预期提升: 方案具体性可提升到 8/10

下一步: 根据改进建议完善方案，重新评估（第1/3轮）
```

### 步骤 6: 完善方案（如果需要）

如果评分 < 9.0，根据评估反馈完善方案：

1. 读取 `iteration/round-1/evaluation.md`
2. 根据改进建议调整 `solution.md`
3. 重新调用 solution-evaluator agent
4. 最多重复3次

### 步骤 7: 实施改进（如果评分 ≥ 9.0）

```bash
# 1. 备份当前 skill
cp SKILL.md SKILL.md.backup

# 2. 按照 solution.md 实施改进
# (修改 SKILL.md，新增文件等)

# 3. 运行测试用例验证
# (确保没有破坏现有功能)

# 4. 更新迭代历史
# 在 feedback/迭代历史.md 中添加本次迭代记录
```

## 🎯 关键点

1. **记录坑点要详细**: 包含足够的上下文信息
2. **评估是自动的**: 脚本会检查是否达到阈值
3. **方案质量把关**: 9分的高标准确保质量
4. **最多3轮迭代**: 避免无限循环
5. **人工决策兜底**: 3轮后不达标需要人工介入
